## 0. Precondition in REPO (re-verified)

- `TableType` enum in `openmetadata-spec/src/main/resources/json/schema/entity/data/table.json:27-42` has `Regular, External, Dynamic, View, SecureView, MaterializedView, Iceberg, Local, Partitioned, Foreign, Transient, Stream, Stage, SemanticView`. **No `DeltaLake` value exists in this worktree** (grep for "Delta" in table.json matches only the compression-codec description at :1236). So for every connector built on `CommonDbSourceService` (athena, redshift, trino, presto, hive, impala, iomete, starrocks, doris, clickzetta) a partitioned Iceberg (and a future partitioned DeltaLake) table ends up `Partitioned`, not the detected type. Glue (own `yield_table`, glue/metadata.py:344) and datalake (own `yield_table`, datalake/metadata.py:257) do not have this override. Whoever implements DeltaLake must decide precedence.

## 2. Glue

1. **Can host Delta?** Yes. AWS Glue: "AWS Glue 3.0 and later supports the Linux Foundation Delta Lake framework." (https://docs.aws.amazon.com/glue/latest/dg/aws-glue-programming-etl-format-delta-lake.html). Athena: "Native Delta Lake support is supported only through tables registered with AWS Glue." (https://docs.aws.amazon.com/athena/latest/ug/delta-lake-tables.html). Crawler: "Glue crawler is adding support for creating AWS Glue Data Catalog tables for native Delta Lake tables and does not require generating manifest files." (https://aws.amazon.com/blogs/big-data/introducing-native-delta-lake-table-support-with-aws-glue-crawlers/). Athena engine version 3 only.
2. **Current listing / type decision.** `_get_glue_tables` paginates Glue `get_tables` (glue/metadata.py:128-141). `get_tables_name_and_type` (:278) sets `is_view = table.TableType == "VIRTUAL_VIEW"` (:296), reads `parameters = table.Parameters` (:321), then the ladder: `parameters.table_type == "ICEBERG"` -> Iceberg (:324-327); `table.TableType == "EXTERNAL_TABLE"` -> External; `VIRTUAL_VIEW` -> View. Model: `glue/models.py:28-33` `TableParameters` has `extra="allow"` so unknown keys survive (verified by running plain pydantic: `spark.sql.sources.provider` lands in `model_extra` and `model_dump()`).
3. **Indicator, exact strings and case.** Three distinct producers write three different shapes; the matrix's single `table_type == 'DELTA'` is incomplete:
   - Athena `CREATE EXTERNAL TABLE ... TBLPROPERTIES ('table_type' = 'DELTA')` (getting-started page: https://docs.aws.amazon.com/athena/latest/ug/delta-lake-tables-getting-started.html, "`TBLPROPERTIES ('table_type' = 'DELTA')`"). Uppercase in the doc example. The Glue-side stored form is not shown in any doc I fetched (UNVERIFIED).
   - The Athena "Synchronize Delta Lake metadata" page (https://docs.aws.amazon.com/athena/latest/ug/delta-lake-tables-syncing-metadata.html) says the opposite for its DDL: "when using this method, the value for `TBLPROPERTIES` must be `'spark.sql.sources.provider' = 'delta'` and not `'table_type' = 'delta'`." Its CLI example creates Glue `Parameters: {"EXTERNAL": "TRUE", "spark.sql.sources.provider": "delta"}` with no `table_type`.
   - Glue crawler native table (blog sample `get-table` output, dated 2022, current behaviour UNVERIFIED): Table `Parameters` contain `"classification": "delta"`, `"spark.sql.sources.provider": "delta"`, `"table_type": "delta"` (**lowercase**), `"spark.sql.sources.schema.part.0": "{...}"`, `"delta.lastCommitTimestamp"`, `"delta.lastUpdateVersion"`. Same keys also appear under `StorageDescriptor.Parameters`. Fetched copy: scratchpad `glue_delta_blog.txt`.
   - Spark `saveAsTable` (Glue doc example, `.format("delta")...saveAsTable(...)`): key set not printed in the Glue doc; the Athena sync page states Spark-created tables get the placeholder schema (see 5) and the Trino reader keys off `spark.sql.sources.provider`.
   - Trino's own metastore reader: `SPARK_TABLE_PROVIDER_KEY = "spark.sql.sources.provider"`, `DELTA_LAKE_PROVIDER = "delta"`, `return DELTA_LAKE_PROVIDER.equalsIgnoreCase(tableParameters.get(SPARK_TABLE_PROVIDER_KEY));` (https://raw.githubusercontent.com/trinodb/trino/master/plugin/trino-hive/src/main/java/io/trino/plugin/hive/util/HiveUtil.java, lines 144-145 and 785-787 when fetched via curl; Iceberg check at 148-149/795-797 is `equalsIgnoreCase` too). So case-insensitive is the upstream convention; the OM Iceberg check at glue/metadata.py:324 is exact-match uppercase.
   - False positives: `table_type` is a shared key (Iceberg uses `ICEBERG`); comparing to `delta` cannot match Iceberg. `spark.sql.sources.provider` is set for all Spark datasource tables (value differs: parquet, csv, ...), so equality to `delta` is specific. Open question, UNVERIFIED: Delta UniForm/Iceberg-compatible tables might carry both `table_type=ICEBERG` and `provider=delta`; the existing ladder would then win with Iceberg. Per-table indicator.
4. **Already accessible?** Yes, zero extra calls: `table.Parameters` is in the `get_tables` page (Glue GetTables returns full `Table` objects incl. `Parameters`, https://docs.aws.amazon.com/glue/latest/webapi/API_GetTables.html; `Parameters` = "These key-value pairs define properties associated with the table."). Code already holds it at glue/metadata.py:321.
5. **Metadata for a Delta table today.** Columns: `StorageDescriptor.Columns` + `PartitionKeys` (glue/metadata.py:437-533); the Iceberg branch does an extra `glue.get_table` per Iceberg table (:466-491) but a Delta branch would not need it. Location -> `locationPath` (:390). `fileFormat=self.get_format(...)` (:389, :536-544) uses `SerdeInfo.SerializationLibrary`: the crawler sample has `LazySimpleSerDe` with `serialization.format: "1"`, so **current code would set fileFormat `csv` on a crawler-created Delta table** (CODE-READ + blog sample; a misreport unrelated to detection but visible on the same entity). Partitions: `PartitionKeys` are emitted as columns only; there is no `tablePartition` for Glue. Degenerate case, DOC-QUOTED: "Note that this same schema (with a single of column named `col` of type `array<string>`) is inserted when you use Apache Spark (Athena for Apache Spark) or most other engines to create your table." (Athena sync page). Athena-created tables: "Athena synchronizes table metadata, including schema, partition columns, and table properties, to AWS Glue if you use Athena to create your Delta Lake table." Crawler-created: real columns plus the Spark schema JSON (blog). Delta docs on why: "the table definition in the metastore may not contain all the metadata like schema and properties. It contains the location of the table, and the table's transaction log at the location is the source of truth." (https://raw.githubusercontent.com/delta-io/delta/master/docs/src/content/docs/delta-batch.mdx, "Note" aside near line 318-325). With `includeCustomProperties`-style extension (:404-) all Parameters, including `spark.sql.sources.schema.part.0`, could be dumped as custom properties.
6. **Verdict: IMPLEMENTABLE-NOW.** The keys are in the object the code already holds; the only work is a case-insensitive check on both `table_type` and `spark.sql.sources.provider` (via `parameters.model_extra`) inserted before/after the Iceberg branch at glue/metadata.py:324, plus deciding precedence versus `VIRTUAL_VIEW` (Iceberg already wins over view, test at test_glue.py:786-830).

## 4. Redshift

1. **Can host?** Only via manifest. DOC-QUOTED (https://docs.aws.amazon.com/redshift/latest/dg/c-spectrum-external-tables.html): "To access a Delta Lake table from Redshift Spectrum, generate a manifest before the query." and "For Delta Lake tables, you define `INPUTFORMAT` as `org.apache.hadoop.hive.ql.io.SymlinkTextInputFormat` and `OUTPUTFORMAT` as `org.apache.hadoop.hive.ql.io.HiveIgnoreKeyTextOutputFormat`. The `LOCATION` parameter must point to the manifest folder in the table base folder." Delta docs: manifest is written to `<path-to-delta-table>/_symlink_format_manifest/` (https://raw.githubusercontent.com/delta-io/delta/master/docs/src/content/docs/redshift-spectrum-integration.mdx line 61). Glue crawler blog: native Delta tables "are accessible from Amazon Athena (engine version 3), AWS Glue for Apache Spark ..., Amazon EMR ..."; symlink tables "are accessible from Amazon Athena and Amazon Redshift Spectrum" (Redshift Spectrum not listed for native). Redshift can still *list* native Delta Glue tables in an external schema (they are just Glue tables); whether it lists them is UNVERIFIED.
2. **Current path.** `RedshiftSource.query_table_names_and_types` (redshift/metadata.py:193-226) runs `REDSHIFT_GET_ALL_RELATION_INFO` (redshift/queries.py:162-178): local relations from `pg_class` plus `SELECT tablename as name, 'e' as relkind FROM svv_external_tables WHERE schemaname = :schema`; type comes from `STANDARD_TABLE_TYPES` (`e` -> External, metadata.py:111-116, :224). Location: separate per-database query `REDSHIFT_EXTERNAL_TABLE_LOCATION` = `SELECT schemaname, tablename, location FROM svv_external_tables where redshift_database_name = :database_name` (queries.py:273-277) loaded by `set_external_location_map` (metadata.py:275-282). A second external listing `REDSHIFT_GET_ALL_RELATIONS` (queries.py:~370-395) also reads `svv_external_tables`.
3. **Indicator.** `SVV_EXTERNAL_TABLES` columns (DOC-QUOTED, https://docs.aws.amazon.com/redshift/latest/dg/r_SVV_EXTERNAL_TABLES.html): `redshift_database_name, schemaname, tablename, tabletype, location, input_format, output_format, serialization_lib, serde_parameters, compressed, parameters` ("parameters | text | Table properties."). For symlink-manifest Delta: `input_format = org.apache.hadoop.hive.ql.io.SymlinkTextInputFormat` (exact case per doc) and `location` ending `_symlink_format_manifest`. False-positive risk: `SymlinkTextInputFormat` is a generic Hive symlink format (any manifest-based table), so it needs the location suffix, and the suffix is a Delta-tool convention, not a Redshift-enforced value. Per-table. For native Delta Glue tables surfaced in Redshift, the `parameters` text may contain `spark.sql.sources.provider`; the doc gives no format for that text: UNVERIFIED.
4. **Accessible now?** No: the queries at queries.py:162-178 and :273-277 project only `tablename`/`location`. Extra work is a projection change (add `input_format`, `parameters` to the `svv_external_tables` selects), not an extra round trip per table, but the type is decided at listing time (`STANDARD_TABLE_TYPES`), so the listing query must carry the columns.
5. **Metadata.** External columns from `svv_external_columns` (queries.py:~240-267), Hive-style types; location via the location map (metadata.py:173-177 `get_location_path`); partitions for external tables per Redshift docs need `ALTER TABLE ADD PARTITION` (manifest is partitioned); the schema is the schema declared on the symlink table, not read from the transaction log.
6. **Verdict: IMPLEMENTABLE-WITH-EXTRA-WORK.** Extend the `svv_external_tables` projection with `input_format`+`location` for the manifest shape; product decision needed on whether a symlink-manifest snapshot counts as a "DeltaLake table" (its `locationPath` points to `_symlink_format_manifest`, not the Delta root); native-in-Glue shape unverifiable without a live cluster.
