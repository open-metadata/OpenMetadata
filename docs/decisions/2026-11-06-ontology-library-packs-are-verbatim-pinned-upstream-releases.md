# Ontology library packs are verbatim pinned upstream releases

- **Status:** Accepted
- **Revisions:** v1 2026-11-06 (initial); v2 2026-11-07 (GS1 EPCIS and CBV included pending confirmation); v3 2026-11-07 (verbatim triples: converted-to-Turtle sources; IOF Core and Supply Chain added); v4 2026-11-07 (IOF pack covers every Released module of the production release); v5 2026-11-08 (bounded browsing caches and summary responses)
- **Deciders:** OpenMetadata maintainers
- **Guard:** `python3 scripts/ontology-packs/generate.py --check` (`make ontology-packs-check`, also a `make harness-check` warning), OntologyPackCatalogTest, OntologyPackVerifierTest, BundledOntologyPackImportTest, NativeOntologyEveryPackInstallIT
- **Related:** ADR:2026-10-19-native-ontology-imports-use-working-drafts

## Context

The library packs were four- to ten-concept SKOS sketches written by us, under IRIs we invented (`https://open-metadata.org/library/...`), and named FIBO, FHIR and GS1. A user who installed "FIBO" got concepts that no FIBO document, mapping or SPARQL query recognises. Importing a real standard is now possible because the native importer keeps what it can hold and reports the rest (ADR:2026-10-19-native-ontology-imports-use-working-drafts), so the sketches no longer earn their place where an open, permissively licensed ontology exists.

## Decision

A bundled pack is an upstream release, byte for byte, at a pinned URL, with the publisher's IRIs. `scripts/ontology-packs/sources.json` holds one entry per pack (publisher, version, pinned URL, `sourceSha256`, license and license URL, attribution text, industry, layer, modules). `scripts/ontology-packs/generate.py`, which needs only the Python standard library, is the only writer of the payloads under `openmetadata-spec/src/main/resources/rdf/ontology-packs/`, the manifests and `index.json` under `openmetadata-service/src/main/resources/json/data/ontology/packs/`, the payload README, and the generated block of `NOTICE`. It downloads a payload only when the checked-in file does not already match its pinned hash, so a second run changes nothing, and `--check` verifies everything offline. It never converts a format: Turtle stays Turtle and RDF/XML stays RDF/XML, because the importer reads both. A publisher that changes a pinned file fails the run until a maintainer reviews it and re-pins.

A pack ships only when its license permits redistribution inside an Apache-2.0 distribution with attribution. The generator rejects any license that is not in `allowedLicenses` of the source list: CC BY 4.0 and 1.0, CC0, MIT, BSD-3-Clause, Apache-2.0, the W3C Software and Document and Document licenses, and the Open Data Commons PDDL. A pack names its attribution in the manifest, the Library detail shows it, and `NOTICE` carries it.

These are not bundled, and the source list records the reason for each: schema.org (CC BY-SA 3.0 share-alike needs counsel), DCMI Terms (license unconfirmed), SAREF (the ETSI license text could not be read), QUDT (not evaluated; its header carries a UCUM notice), ISA-95 (a paid standard) and HR Open (no RDF form). Reversing an exclusion needs a new record.

ISA-95 and HR Open keep an OpenMetadata-authored starter, renamed `<Standard> Starter (OpenMetadata-authored)`, licensed Apache-2.0 as part of OpenMetadata, and described as aligned to the standard. A starter never claims to be a subset or a copy of it.

A manifest counts a module's `conceptCount` as the distinct IRIs typed `owl:Class`, `rdfs:Class` or `skos:Concept` in its file, and `relationshipCount` as the distinct IRI-to-IRI `rdfs:subClassOf`, `rdfs:subPropertyOf` and `skos:broader`, `narrower` and `related` statements. They describe the file, so a module that re-declares terms of its dependency counts them again.

Every pack installs through the library install job, whatever its size: there is no per-pack install mode. The preview, review and sample of a pack read its modules through the trusted parser, against their catalogue checksums, and are not held to the 1,000 changed definitions that one interactive native import accepts. The review lists at most 5,000 items. Every pack fits the 50,000-member ontology limit. `BundledOntologyPackImportTest` previews each pack, and `NativeOntologyEveryPackInstallIT` installs each one into a fresh ontology.

The catalogue reads `json/data/ontology/packs/index.json`, which the generator writes, instead of a hard-coded list. A missing index, a missing or malformed manifest, or a manifest whose `id` differs from its file name stops the server at startup.

**Amendment v2: GS1 EPCIS and CBV are included pending confirmation.** GS1 publishes the EPCIS 2.0.1 and CBV 2.0.1 ontology files openly at ref.gs1.org. The files carry no license statement, and we found no GS1 terms that grant or refuse redistribution. The product owner decided to include them. The `epcis` pack ("GS1 EPCIS 2.0 and CBV") holds both files verbatim as two modules, `cbv` and `epcis` (which depends on `cbv`), and replaces the OpenMetadata-authored EPCIS starter. Its license is recorded as "No license statement published by GS1; included pending confirmation", a value `allowedLicenses` lists by name so no other unlicensed pack can slip in. If GS1 tells us we cannot redistribute them, we remove the pack and ship that in a release: delete the `epcis` entry from `sources.json`, run `make ontology-packs` (it deletes the payloads, manifest and NOTICE entry), and release. An installation already made keeps its concepts, as with any pack the catalogue stops offering.

**Amendment v3: verbatim triples, and the IOF ontologies as a full manufacturing pack.** "Verbatim bytes" becomes "verbatim triples". A source we cannot parse as published is converted to Turtle by the generator. The case is an RDF/XML file that opens with a DOCTYPE declaring internal entities: the XXE guard in `SafeRdfModelParser` refuses every DOCTYPE on every path, `parseTrusted` included, and that guard does not change. A module that declares `"convert": "turtle"` in `sources.json` is downloaded, checked against its pinned `sourceSha256` as before, converted with rdflib, proved isomorphic to the source graph (same triple count, rdflib graph isomorphism), and written as sorted N-Triples-style Turtle with canonical, module-unique blank-node labels (the preview joins module bodies, so labels must not repeat across modules), so a rerun is byte-identical. `sources.json` records both `sourceSha256` (the published file) and `payloadSha256` (the stored Turtle); the manifest's `sha256` is the payload hash and its `sourceSha256` is the published-file hash. `make ontology-packs-check` stays offline and standard-library only: it compares the checked-in payload to `payloadSha256`. rdflib is a dev-only dependency, imported only when a conversion runs; a run that finds every payload current never loads it. IRIs, literals and structure are the publisher's; only the serialization differs. The `iof` pack ("Industrial Ontologies Foundry (IOF)", release 202603) is the first user. It holds four modules pinned to commit `0c5af080dba16489db1b5c7a432a34222524c6e9` of `iofoundry/ontology` (tag `Release_202603`) so a moved tag cannot change the source: `bfo`, `annotation-vocabulary`, `core` (depends on both) and `supply-chain` (depends on `core`). All four are converted, because the pack loader requires one RDF format per selection. The `bfo` module is IOF's own cached copy `cache/bfo/2020/bfo.rdf`, not the BFO purl, which now redirects to a different profile of BFO. IOF is MIT licensed; BFO is CC BY 4.0. A manifest records one license per pack, so the pack license is "MIT; BFO module CC BY 4.0", which `allowedLicenses` lists by name, and the attribution carries both notices and the Open Applications Group copyright of the Supply Chain module. The ISA-95 starter stays as the OpenMetadata-authored outline aligned to the standard; the Library presents IOF as the full manufacturing ontology.

**Amendment v4: the IOF pack mirrors IOF's production release.** The `iof` pack holds every module that a `*/AboutIOFProd.rdf` manifest at `Release_202603` imports and marks `iof-av:maturity Released`, and nothing else. Beyond the four v3 modules that is `maintenance` and `certification` (each imports Core) and the thirteen biopharma modules `biopharma/AboutIOFProd.rdf` imports. Every module's own `owl:imports` was read: all point at Core, Supply Chain, Certification or another Released biopharma module, never at a Provisional module, a Dev-only module or a `cache/` file other than BFO, so the dependency closure is the pack itself, and `sources.json` lists modules dependencies first. Provisional and development modules (production planning, product-service-system, the biopharma Statistics, Design of Experiments, deviation, risk, testing, lifecycle and classification-utility modules, and the Core addenda and mappings) stay out until IOF releases them. Every added module opens with the same entity-declaring DOCTYPE, so all are converted. The pack's attribution now says the Open Applications Group copyright is carried by the IOF modules generally (Core carries it too) and credits ChEBI, from which Molecular Entity adapts terms, under CC BY 4.0.

## Consequences

Adding a pack is one entry in the source list and a run of `make ontology-packs`. An update to a pack is a reviewed re-pin, not an edit of a payload. The jar carries about 18 MB of uncompressed RDF, which the build compresses. A mapping or query written against FIBO, DCAT or PROV-O IRIs works against an installed pack. A user who installed an old starter FIBO keeps its concepts, but its recorded version no longer matches the catalogue, so a later install of the same pack id replaces the record. The import preview of a small pack now reports the statements it skipped, which is most of an upstream OWL file.

Revisit when the licenses of an excluded vocabulary are confirmed, or when a third party needs a pack to be split into modules by the publisher.

## Amendment v5: reuse bundled sources while reviewing the current draft

Library browsing reuses checksum-verified native documents and completed samples for the same dependency-expanded module selection. The cache key includes the pack version and each selected module's identity, resource path, format and pinned checksum. Production sampling and review share the document cache. Bundled classpath resources are immutable for the lifetime of the process; a new bundle starts a new cache.

Sample traversal indexes child IRIs by relation target once and preserves the sorted breadth-first selection. It does not rescan every relation for each candidate concept. The chain regression in `OntologyPackSamplerTest` checks the selected concepts and relations together with a relation-read budget.

Documents have a 64 MiB retained serialized-payload budget and samples have a separate 4 MiB budget. Each entry is charged at least 16 KiB to bound the number of small entries as well. Cache misses for the same selection share one computation. Entries retain private serialized bytes and decode a fresh object for each caller, because the generated definition and sample models are mutable. These budgets do not claim to bound peak JVM heap or the transient allocation of a cold parse.

The Library uses `POST /ontologies/{id}/library/{packId}/summary`, which returns `NativeOntologyImportSummary` without a change set. It retains the 5,000-item listing limit and total counts. Existing `/review` and `/preview` response contracts remain available. Summaries and change sets are never cached: every request reads and authorizes the current working draft, then computes its statuses and clash warnings. The install job continues to reconstruct its own plan from verified bundled content.

`OntologyPackModelsTest`, `OntologyPackSamplerTest` and `NativeOntologyLibraryPreviewIT` guard reuse, mutation isolation, eviction, response bounds and current-draft authorization. A cold selection still parses and reconciles the whole pack; a warm summary still reconciles the current draft.
