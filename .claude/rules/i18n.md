# i18n

Applies to UI `*.{ts,tsx}` and `src/locale/**`. Primary catalog:
`openmetadata-ui/src/main/resources/ui/src/locale/languages/en-us.json`.

- **No string literals in the UI.** Use the `useTranslation` hook —
  `const { t } = useTranslation();` — and reference keys: for the text "Run", write `{t('label.run')}`
  with the label defined in the locale files. This applies to JSX text and any user-facing string.
- Keys are added to `en-us.json` (kebab-case, under the right namespace: `label`, `message`, `server`).
- **After adding keys, run `yarn i18n`** to propagate them into **every other locale file**
  (`sync-i18n`, primary `en-us`). CI's i18n step fails if the locales are out of sync.
- **JSON keys must stay alphabetically sorted** in `src/locale/**/*.json`.
- **Translate the placeholders `yarn i18n` inserts.** `yarn i18n` copies the English string verbatim
  into each locale as a placeholder — you **must** then replace those placeholders with real
  translations in every non-`en-us` file. Shipping English text under a non-English locale key is a
  reviewable defect. Leaving a term in English is allowed **only** as a deliberate translation
  decision (a widely-borrowed acronym like "AI", or a product name) — never as a "yarn i18n did it"
  default.

> **Corrected count (was wrong in the old CLAUDE.md):** `yarn i18n` syncs **19 non-English locale
> files (20 total including `en-us.json`)** — the old "17 locale files" figure was incorrect.
> Note that CI only verifies keys are *synced*, not that placeholders were *translated* — that part
> is enforced by review, not automation.
